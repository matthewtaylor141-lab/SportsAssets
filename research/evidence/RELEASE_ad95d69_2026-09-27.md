
`1d2db59` is an ancestor of `ad95d69` by **37 commits**. Both readbacks I read in

> deployed but their behaviour in the scheduled path is **not yet read back**, so
> the register's "deployed evidence: none" for that work stands.

### A security finding the readback surfaced

```
OPERATOR_PASSWORD present in the service environment   yes
DESK_PASSWORD present in the service environment       NO
```

**`DESK_PASSWORD` is not set**, so the read sign-in is protected by the default in
`backend/sportsassets/config.py` — **which is published in this repository.** The
readback signed in with that default and said so, rather than reporting "not
configured" and moving on. Read access to the Command Centre is therefore
effectively open to anyone who reads the source. **That is an owner decision to
make** — set `DESK_PASSWORD` on the service — and it is not something this
release can fix from the code side.

### And what a deploy is not

The serving build being `ad95d69` establishes that this code runs. It establishes
nothing about whether the strategy earns, whether an account is eligible, or
whether an order could be placed — all three are separately blocked, and
`funded_submission` reads `DISABLED` in the same readback.
