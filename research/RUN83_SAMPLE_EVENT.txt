==========================================================================
SAMPLE SHADOW EVENT -- produced by RUNNING the collector, not hand-written
==========================================================================
Fake venue, fake pool, no database, no network, no order path. The
pre-registered offsets are shortened to 0/100/250 ms so one event completes
inside a process, and the fake venue's ask walks half a cent per read so the
curve visibly moves -- that movement is the whole thing the instrument exists
to capture prospectively.

Read three things in particular:

  * source_ts_provenance / source_ts_clock_domain / source_ts_status travel
    BESIDE the value. A later reader never has to infer which clock produced
    it, which is the failure run 82 could not undo.
  * venue_snapshot_ts and venue_sequence are null. Honestly: no book or BBO
    response this repository reads carries either. That absence is a run 83I
    finding, not a gap in the sample.
  * receipt_monotonic is meaningful only against process_boot_id. Across a
    restart the monotonic origin moves, and obs/clock.py RAISES rather than
    subtract across that boundary.
